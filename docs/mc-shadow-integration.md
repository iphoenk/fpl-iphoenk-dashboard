# Offline MC to Vercel: shadow boundary

The existing private Blob store supplies a fixed `mc-shadow/v1/latest.json` record. A separate read-only `/api/mc/shadow` endpoint validates transport integrity, strict player-only schemas, pinned engine ownership/revision, Official identity, season/GW/deadline, complete global coverage and six-hour maximum input age. It returns operational metadata only. No private forecast rows, player projections, input fingerprints, manager state or raw upstream errors reach the browser.

Universe means every player in the current trusted Official FPL bootstrap, for every GW in the selected horizon. There is no 300-player sample or 1000-player ceiling in the acceptance logic. Missing, additional or duplicate player/GW pairs reject the entire snapshot. Byte-size limits reject oversized artifacts explicitly; they never truncate the player universe. A synthetic regression covers 1501 players across five GWs (7505 rows); this is a scaling contract test, not 1501 real Official players or real MC execution.

`FPL_MC_BLOB_RECORD_V1` wraps the exact UTF-8 Python candidate JSON plus its SHA-256. Hashing the raw bytes avoids Python `2.0` versus JavaScript `2` serialization differences. Hash integrity does not authenticate a model; the private publication channel and governed exporter are still required. The nested `FPL_MC_PLAYER_SNAPSHOT_V1` remains SHADOW_ONLY and explicitly noncanonical.

Official facts remain authoritative. V12_PLAYER_MINUTES and V12_MONTE_CARLO retain their owners. Marginal summaries do not recreate route correlations, autosubs or captain takeover. V12 Lite continues deterministic selection; this change does not replace or multiply its xP.

The new endpoint has a bounded operation budget, short per-instance caching/singleflight and an abort signal. It reads Blob before requesting Official bootstrap, so missing MC output does not trigger Official calls. Success cache expires at snapshot expiry; no stale-on-error. The main `/api/decision` code does not import or call it, so optional MC storage cannot delay A/B/C. `FPL_MC_SHADOW_ENABLED=0` disables the reader. Alternative Worker returns an explicit unavailable response for this private-storage integration.

An offline publication command validates the candidate against fresh Official bootstrap before writing only the dedicated private MC path and checking readback. It requires existing Blob credentials through the environment; none are copied to GitHub or browser. No HTTP upload route, arbitrary URL proxy, scheduler, new database or second Vercel project is added.

Acceptance plan: tests first for Python-to-JS raw transport, null/nonfinite/private fields, wrong identity/GW/owner/revision, expiry/deadline, missing coverage, bad methods/query, missing storage, bounded slow storage, coalescing and expiry. Verify both builds, browser parse, existing full suite, MC repository suite and protected preview. Do not label missing output as a real MC pass. Actual engine exporter/parity and any numeric effect require subsequent reviewed changes.
